# سامانه جامع دانشجویی دانشگاه صنعتی وزیر

نسخه رسمی سامانه جامع دانشجویی دانشگاه صنعتی وزیر، توسعه‌یافته با پشته مدرن فول‌استک:
- **فرانت‌اند**: React 19، TypeScript، Tailwind CSS v4، Motion
- **بک‌اند**: Node.js (نسخه ۲۲ به بالا)، Express
- **پایگاه داده**: SQLite نیتیو (`node:sqlite`) در حالت WAL
- **امنیت**: نشست‌های رمزنگاری‌شده (Signed HttpOnly Cookies)، هش امن کلمات عبور با الگوریتم `scrypt`، محدودکننده نرخ درخواست (Rate Limiting) و ایزولاسیون کامل سطح دسترسی دانشجویان و ادمین
- **هوش مصنوعی**: دستیار دانشجویی هوشمند با Gemini AI (اختیاری)

---

## 📋 متغیرهای محیطی (Environment Variables)

برای راه‌اندازی، فایل `.env` را از روی `.env.example` بسازید:

```bash
cp .env.example .env
```

| متغیر | مقدار پیش‌فرض | الزامی؟ | توضیحات |
| :--- | :---: | :---: | :--- |
| `PORT` | `3000` | اختیاری | پورت شبکه سرور |
| `TRUST_PROXY` | `1` | توصیه‌شده | تعداد هاپ‌های پروکسی معکوس (مانند Nginx یا Caddy) جهت تشخیص دقیق IP و پروتکل HTTPS |
| `DATA_DIR` | `./data` | اختیاری | مسیر ذخیره‌سازی فایل پایگاه‌داده SQLite و سکرت سشن‌ها |
| `SESSION_SECRET` | *(رندوم ۳۲ بایتی)* | توصیه‌شده | کلید امضای کوکی سشن‌ها. در صورت خالی بودن، به طور خودکار در فایل `.session_secret` تولید و ذخیره می‌شود |
| `ADMIN_EMAIL` | - | الزامی برای ادمین | ایمیل اولیه حساب مدیر سیستم |
| `ADMIN_PASSWORD` | - | الزامی برای ادمین | کلمه عبور حساب مدیر سیستم (حداقل ۶ کاراکتر) |
| `ADMIN_NAME` | `مدیر سیستم` | اختیاری | نام نمایشی مدیر سیستم |
| `GEMINI_API_KEY` | - | اختیاری | کلید API گوگل جمینای جهت فعال‌سازی چت‌بات هوشمند دستیار آموزشی |

## 🚀 نحوه اجرای محلی (Local Development)

### ۱. نصب وابستگی‌ها
پروژه به Node.js نسخه **22.5 یا بالاتر** نیاز دارد (برای پشتیبانی بومی از `node:sqlite`):

```bash
node -v   # باید بالاتر از v22.5 باشد
npm install
```

### ۲. اجرای در حالت توسعه (Dev Server)
```bash
npm run dev
```
سرور در آدرس `http://localhost:3000` آماده به کار خواهد بود و تغییرات فرانت‌اند به صورت زنده با Vite بارگذاری می‌شوند.

## 🏗️ بیلد و اجرای نسخه پروداکشن (Build & Production)

### ۱. ساخت بیلد نهایی
```bash
npm run build
```
این دستور:
1. فایل‌های فرانت‌اند را با `vite build` در پوشه `dist/` کامپایل می‌کند.
2. سرور Express را با `esbuild` در فایل باندل `dist/server.cjs` بیلد می‌نماید.

### ۲. اجرای سرور پروداکشن
```bash
npm start
```
سرور استاتیک و APIها به صورت یکپارچه با پورت مشخص‌شده شروع به کار می‌کنند.

## 💾 پشتیبان‌گیری و بازیابی داده‌ها (Backup & Restore)

پایگاه داده به صورت مستقل در قالب JSON (شامل کاربران بدون هش پسورد و پیام‌های چت) قابل خروجی‌گرفتن و بازیابی است.

> ⚠️ **هشدار حیاتی درباره ذخیره‌سازی بک‌آپ‌ها در کانتینر (Ephemeral Storage Warning):**
> فایل‌های پشتیبان ذخیره‌شده روی همان دیسک لوکال کانتینر (مانند پوشه `backups/`)، با ری‌استارت، دیپلوی مجدد، اسکیل یا تخریب کانتینر (به عنوان مثال در Cloud Run، Docker یا کوبرنتیز بدون Persistent Volume) **به طور کامل و غیرقابل بازگشت پاک می‌شوند!**
> بنابراین **حتماً و بلافاصله پس از ایجاد بک‌آپ، فایل را دانلود نموده** (از طریق اندپوینت `GET /api/admin/backup` یا کپی فایل به فضای امن خارج از کانتینر / باکت‌های ذخیره‌سازی ابری مثل S3 یا GCS) و در سرور نگه ندارید.

---

### ویژگی‌های امنیتی بازیابی (Restore Security & Reliability)

۱. **بک‌آپ خودکار پیش از بازیابی (Auto Pre-Restore Backup):**
   - سیستم پیش از اعمال هرگونه تغییر روی دیتابیس در هنگام Restore، به صورت خودکار یک نسخه پشتیبان از وضعیت فعلی در مسیر `backups/pre-restore-<timestamp>.json` ایجاد می‌کند تا در صورت بروز هرگونه مغایرت، دیتابیس قبلی در دسترس باشد.
   - بازیابی در قالب یک تراکنش اتمیک (`BEGIN IMMEDIATE` / `COMMIT`) اجرا می‌شود و در صورت بروز کوچک‌ترین خطا به صورت کامل `ROLLBACK` می‌گردد.

۲. **اعتبارسنجی دقیق و محدودیت‌های حجمی (Strict Validation & Limits):**
   - **حداکثر حجم فایل بک‌آپ:** ۱۰ مگابایت (10 MB).
   - **سقف رکورد کاربران:** حداکثر ۵٬۰۰۰ کاربر در هر بسته بازیابی.
   - **سقف رکورد پیام‌ها:** حداکثر ۲۰٬۰۰۰ پیام چت در هر بسته بازیابی.
   - **بررسی صحت ساختار:** اعتبارسنجی فرمت ایمیل، طول نام، سطح نقش (جلوگیری از ارتقای دسترسی غیرمجاز)، و ایمن‌سازی فیلد پروفایل در برابر حملات Prototype Pollution.

---

### وضعیت لاگین کاربران پس از بازیابی (User Credentials After Restore)

- **چرا نسخه‌های پشتیبان فاقد هش پسورد هستند؟**
  برای حفظ امنیت و حریم خصوصی، خروجی بک‌آپ هرگز شامل فیلد حساس `password_hash` نمی‌شود تا نشت فایل بک‌آپ منجر به افشای اطلاعات احراز هویت نگردد.
- **کاربران موجود در پایگاه داده فعلی:**
  اگر کاربری از قبل در دیتابیس وجود داشته باشد، اطلاعات پروفایل او به‌روزرسانی شده اما پسورد قبلی وی حفظ می‌شود و می‌تواند طبق روال گذشته لاگین کند.
- **کاربران جدید بازیابی‌شده:**
  کاربرانی که قبل از بازیابی در دیتابیس وجود نداشته‌اند، با یک هش تصادفی و غیرقابل حدس ایجاد می‌شوند؛ لذا با پسورد قبلی خود امکان ورود مستقیم نخواهند داشت.
- **راهکار امن ورود:**
  - **حساب ادمین:** با متغیرهای محیطی `ADMIN_EMAIL` و `ADMIN_PASSWORD` در زمان راه‌اندازی سرور به صورت خودکار همگام‌سازی و بازنشانی می‌شود.
  - **دانشجویان:** فرآیند بازیابی رمز عبور / فعال‌سازی حساب از طریق درگاه دانشجویی یا تنظیم رمز موقت توسط مدیر سیستم انجام می‌پذیرد.

### روش اول: از طریق خط فرمان (CLI Scripts)

#### تهیه بک‌آپ:
```bash
npm run backup
```
فایل پشتیبان در پوشه `backups/backup-<timestamp>.json` ذخیره خواهد شد. همچنین می‌توانید مسیر دلخواه مشخص کنید:
```bash
npx tsx scripts/backup.ts /path/to/my-backup.json
```

#### بازیابی از بک‌آپ (همراه با تهیه بک‌آپ خودکار پیش از اعمال):
```bash
npm run restore backups/backup-<timestamp>.json
```

---

### روش دوم: از طریق API مدیریتی (Admin Only)

- **دریافت و دانلود نسخه پشتیبان**:
  - متد: `GET /api/admin/backup`
  - دسترسی: نیازمند لاگین با نقش `admin`
  - خروجی: دانلود فایل JSON با نام‌گذاری تاریخ‌دار، شامل ساختار کاربران و پیام‌ها

- **بازیابی نسخه پشتیبان**:
  - متد: `POST /api/admin/restore`
  - دسترسی: نیازمند لاگین با نقش `admin`
  - بدنه درخواست (JSON تا سقف ۱۰ مگابایت):
    ```json
    {
      "users": [...],
      "messages": [...]
    }
    ```
  - خروجی موفقیت:
    ```json
    {
      "message": "Database backup restored successfully",
      "restored": { "restoredUsers": 15, "restoredMessages": 42 },
      "preRestoreBackup": {
        "filePath": "/app/applet/backups/pre-restore-2026-11-10T14-00-00-000Z.json",
        "counts": { "users": 10, "messages": 30 }
      }
    }
    ```

## ⚠️ پایداری داده‌ها (Data Persistence Note)

- فایل دیتابیس در مسیر `data/app.db` (یا مقدار مشخص‌شده در `DATA_DIR`) ذخیره می‌شود.
- در محیط‌های سرور ابری بدون دیسک دائم (مانند کانتینرهای بدون سرور یا پیش‌نمایش Cloud Run)، سیستم فایل موقت (Ephemeral) است؛ بنابراین برای استقرار دائمی در پروداکشن، حتماً یک **Persistent Volume** برای پوشه `data/` متصل کنید.
- همچنین نسخه پشتیبان‌های تولید شده روی دیسک محلی باید بلافاصله دانلود یا به باکت ابری خارجی منتقل گردند.
